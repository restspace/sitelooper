# End-to-end tests

Browser tests for the Snipe-IT web UI, written with [Playwright](https://playwright.dev). They log in as an admin and drive
everyday flows (assets, checkouts and the records they depend on) against a running instance, the way a person would.

## Running locally

1. Serve the app at `http://127.0.0.1:8000`, for example with `php artisan serve --host 127.0.0.1 --port 8000`, on a
   migrated database (`php artisan migrate`) with Passport keys (`php artisan passport:keys`).
2. Seed the e2e baseline. The seeder is idempotent and can be re-run before every test run:

   ```bash
   E2E_ADMIN_PASSWORD='choose-a-password' php artisan db:seed --class=E2eSeeder --force
   ```

   It creates the settings row (if none exists), a superuser (`e2e-admin` unless `E2E_ADMIN_USERNAME` is set) and the
   named records the specs use. See `database/seeders/E2eSeeder.php`.
3. Run the tests from this directory:

   ```bash
   export E2E_ADMIN_USERNAME=e2e-admin
   export E2E_ADMIN_PASSWORD='choose-a-password'
   npm ci
   npx playwright install chromium
   npx playwright test
   ```

Set `E2E_BASE_URL` to test an instance served somewhere else. `npx playwright show-report` opens the HTML report, and
a failed test keeps a trace in `test-results/`.

CI runs the same steps on SQLite in `.github/workflows/tests-e2e.yml`.

## How the specs were written

The specs in `specs/` were generated by [sitelooper](https://github.com/restspace/sitelooper) (MIT) from recorded runs
of the flows. They are plain `@playwright/test` code and need no account, key or service to run or change. The
`*.flow.ts` files are generated; the `*.spec.ts` files are editable test code.
